# Stage 1 – Project Setup: Tasks

## Task 1: Scaffold the NestJS app

**Description:** Create a NestJS TypeScript project in the repository root with strict mode on. Add repository basics so later stages start clean.

**Acceptance criteria:**
- [x] `npm run start:dev` starts the app on port 3000
- [x] `tsconfig.json` has `strict: true`
- [x] `.gitignore` covers `node_modules`, `dist`, `.env` and coverage output; `.gitattributes` forces LF

**Verification:**
- [x] Build succeeds: `npm run build`
- [x] Tests pass: `npm test` (default scaffold tests)

**Dependencies:** None

**Files likely touched:** `package.json`, `tsconfig.json`, `src/main.ts`, `src/app.module.ts`, `.gitignore`, `.gitattributes`

**Estimated scope:** Small (scaffold generated by the Nest CLI)

## Task 2: Docker Compose for PostgreSQL and Redis

**Description:** Add a `docker-compose.yml` that runs PostgreSQL and Redis with health checks and a named volume for database data. Add `.env.example` with every variable the app and Compose need.

**Acceptance criteria:**
- [x] `docker compose up -d` starts both services and `docker compose ps` shows them healthy
- [x] Host ports and database credentials come from `.env`, not hard-coded values
- [x] `.env.example` lists `DATABASE_URL`, `REDIS_URL`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` and the Compose variables, with placeholders only

**Verification:**
- [x] Manual check: `docker compose ps` shows `healthy` for both services
- [x] Manual check: `docker compose exec redis redis-cli ping` returns `PONG`

**Dependencies:** None

**Files likely touched:** `docker-compose.yml`, `.env.example`

**Estimated scope:** Small

## Task 3: Validated config module

**Description:** Load settings with `@nestjs/config` and validate them with a schema at startup. A missing or malformed variable stops the app with a message naming the variable.

**Acceptance criteria:**
- [x] App refuses to start when any of the four required variables is missing, and the error names it
- [x] `STRIPE_SECRET_KEY` must start with `sk_test_` (test mode only, per `PROJECT.md`)
- [x] Other code reads settings through `ConfigService`, never `process.env` directly

**Verification:**
- [x] Tests pass: unit tests for the validation function (valid config, each variable missing, live key rejected)
- [x] Manual check: remove a variable from `.env` and see the startup error

**Dependencies:** Task 1

**Files likely touched:** `src/config/env.validation.ts`, `src/config/env.validation.spec.ts`, `src/app.module.ts`

**Estimated scope:** Small

## Checkpoint: Skeleton
- [x] Tasks 1–3 verified

## Task 4: Prisma setup and PrismaService

**Description:** Install Prisma, point it at `DATABASE_URL` and wrap the client in a `PrismaService` inside a `PrismaModule`. No tables yet; the schema holds only the datasource and generator.

**Acceptance criteria:**
- [x] `npx prisma validate` passes
- [x] `PrismaService` connects on module init and disconnects on shutdown
- [x] `PrismaModule` exports the service so stage 2 can inject it anywhere

**Verification:**
- [x] Build succeeds: `npm run build`
- [x] Manual check: app starts with the database running and logs no Prisma errors

**Dependencies:** Tasks 2, 3

**Files likely touched:** `prisma/schema.prisma`, `src/prisma/prisma.service.ts`, `src/prisma/prisma.module.ts`, `package.json`

**Estimated scope:** Small

## Task 5: Health endpoint

**Description:** Add `GET /health`, which runs `SELECT 1` through Prisma. It returns 200 with `{ "status": "ok" }` when the database answers and 503 when it does not.

**Acceptance criteria:**
- [x] 200 `{ "status": "ok" }` with the database up
- [x] 503 with the database down, and the app keeps running
- [x] No secrets or connection strings appear in the response

**Verification:**
- [x] Tests pass: e2e test for the 200 case; unit test with a mocked Prisma failure for the 503 case
- [x] Manual check: `docker compose stop postgres`, call `/health`, get 503; start it again, get 200

**Dependencies:** Task 4

**Files likely touched:** `src/health/health.controller.ts`, `src/health/health.module.ts`, `src/health/health.controller.spec.ts`, `test/health.e2e-spec.ts`

**Estimated scope:** Small
